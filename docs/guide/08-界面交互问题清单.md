# 界面与交互问题清单（只读审查 + 最小修订方案）

> **本轮只产出清单与方案，没有修改任何界面源码。** 原因见第四节「修订实施前提」——这是工程约束，不是敷衍。
> 审查对象：`src/worker.js` 内嵌的管理页 `PAGE_HTML`（2160–7496）与登录页 `LOGIN_HTML`（7499–7704），以及 `docs/images/` 6 张截图。
> 完整逐条证据（34 条、含原文行号）在仓库外 `M2-M3-docs/raw/` 的界面审查记录中。

## 一、总览

界面工程质量本身不低（九语言、深色模式、安全区、移动端底部抽屉、软删除 5 秒撤销、危险操作密码二次确认、成段帮助文字都在）。问题在于：**它假设用户是能读懂环境变量、Webhook、`/api/push`、令牌的开发者**。

- 共 **34 条**：高 9 / 中 17 / 低 8。
- **A 类 26 条**（纯文案 / 引导 / 纯展示样式，不改业务行为、权限、数据操作）；**B 类 8 条**（涉及业务行为、权限边界或数据操作，**本轮禁止实施**）。
- 一句话结论：**第一次使用的普通用户无法独立走完完整路径**，会在「开启登录」和「备份/导出」两个硬卡点被挡住。

## 三、用户路径卡点（最关键）

| 路径环节 | 用户实际遇到 | 能否独立完成 | 类别 |
|---|---|---|---|
| 部署后第一次打开 | 空列表 +「在手机端配置 SmsForwarder，或调用 /api/push」；**无首次使用向导** | 否（不知第一步） | A（高） |
| **开启登录** | `ENABLE_AUTH` / `ADMIN_PASSWORD` / `SESSION_SECRET` **只能环境变量**，网页里没有开关，也没有一句「请去部署平台设置」 | **否，且无出口指引** | **B-1（权限边界）** |
| 开启后登录 | 只有一个密码框，密码错只说「密码错误」，连续错 5 次锁 10 分钟 | 否（易锁在门外） | A（高） |
| 发送第一条测试消息 | 「发送测试通知」只测**转发渠道**，不往本页写消息；想发一条到页面没有 UI 入口 | 部分 | **B-6（数据写入）** |
| 确认收到 | 只有「测试通知已发送」，无回执、无「去哪看」 | 否 | A + B-3 |
| 找不到消息排错 | 筛选无结果无任何引导 | 否 | A（高） |
| **备份 / 导出** | 导出按钮只在右键/长按才出现的栏里；首页与设置中心都没有入口；点击后**无成功反馈** | **否（几乎发现不了）** | **B-2 + A** |

> 两个**硬卡点**：「开启登录」（B-1，涉及权限边界，需安全评审）与「备份/导出」（B-2，涉及交互可达性）。A 类文案只能缓解，不能根治。

## 四、修订实施前提（为什么本轮不改 `src/worker.js`）

1. `src/worker.js` 是**唯一源**：`gen_app.py` 把它逐字节复制到 `platforms/cloudflare/worker.js`（两者均为 **534787 字节**），并把生成的 `shared/app.js` 逐字节复制到其余五个平台（均为 **536627 字节 / 9060 行**）。
2. **哪怕只改一个字的 UI 文案**，只要不跑生成器写入模式，就会造成六平台界面不一致，而且 `gen_app.py --check` **检测不到**（它只校验 `SCHEMA_SQL` 块与 SQL 引用）。
3. UI 文案在 `3051–4900` 的**九语言字典**里各重复一次，`6230–6255` 的令牌面板还有硬编码中文；零散修改必然出现「部分语言旧文案」。
4. 权限边界：本轮允许「修改不涉及业务行为的界面文案」，但 §七 同时要求「涉及业务行为变化、权限变化或数据操作的改动不得自行实施」。把 A 类文案补丁与生成器**写入模式**绑定，属于需要单独批准的一批改动；本轮保护策略要求不运行生成器写入模式。

**结论**：本轮只输出清单与最小方案，**不落地任何 UI 源码修改**；A 类建议打包成「一次生成器同步的批量文案补丁」在批准后统一实施，流程固定为「改 `src/worker.js` → `python platforms/gen_app.py`（写入模式）→ `--check` → 六副本字节比对 → 九语言字典同步」。B 类 8 项全部走单独审批。

## 五、A / B 分类汇总

**A 类（26 条，本轮仅列方案）**：默认站名与登录页副标题、空状态改写、术语清理（环境变量/403/库内/软删除/Webhook/接口地址）、按钮结果说明、登录框 label 与帮助、`prompt` 示例、渠道凭据获取指引、错误提示下一步、401 刷新前提示、成功反馈文案、删除/合并确认补后果、触摸目标 ≥44px、`title` 说明落成可见文字、手机端危险操作分组样式。

**B 类（8 条，禁止本轮实施）**：

| 编号 | 建议 | 为何是 B |
|---|---|---|
| B-1 | 网页内新增「开启登录 / 设置管理密码」入口 | 改变登录凭据「只走环境变量」的安全模型 |
| B-2 | 新增常驻可见的「选择 / 导出备份」按钮 | 改变功能可达性与信息架构 |
| B-3 | 保存后自动回读设置并回填生效值 | 新增读取与状态展示逻辑 |
| B-4 | 导出改为「生成 → 回执 → 显示条数/失败可重试」 | 改变下载行为与数据流 |
| B-5 | 401 时不自动 reload，保留未保存内容 | 改变会话处理行为 |
| B-6 | 新增「在网页里发一条测试消息」自测入口 | 新增**数据写入**接口 |
| B-7 | 原生 `confirm/prompt` 换成页面内弹层；新增回收站 | 交互改造 / 新增数据恢复操作 |
| B-8 | 新增「退出登录」按钮 | 新增会话/权限操作 |

## 六、建议优先级

1. **先审批两个硬卡点** B-1 / B-2；B-1 尤其要先做安全评审（凭据是否允许迁入网页可写配置）。
2. 再合并实施三条高优 A 类引导：空状态改成界面内可点路径、筛选无结果排错引导、测试通知「去哪确认收到」。
3. 危险操作文案一致性（删除其实可撤销却不说；清空「软删除」与「不可撤销」自相矛盾）优先修。
4. 术语清理与九语言一次性同步；移动端触摸目标与可见说明成本最低。
5. 所有 A 类合并为**一个补丁 + 一次生成器同步**，不要零散改 `src/worker.js`。
