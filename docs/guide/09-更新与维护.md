# 更新与维护

> 完整技术版（含逐版本变更、六平台自愈矩阵、回退路径）：[docs/UPGRADE.md](../UPGRADE.md)。这一篇只保留普通用户要做的四件事。

## 一、如何升级

| 你的部署方式 | 升级动作 | 完成标志 |
|---|---|---|
| Cloudflare / Vercel / Netlify / Deno Deploy（Git 部署） | 在你 Fork 的仓库点 **Sync fork** 同步上游，平台自动重新部署 | 平台显示一次成功部署；页脚版本更新 |
| EdgeOne（Git 导入） | 同上，或在控制台重新触发部署 | 部署详情页状态成功 |
| Node / Docker 自托管 | 拉新代码 → 重新 `docker build` → 用**带 `--stop-timeout=90`** 的命令重启 | 日志出现 `shutdown_grace=80s`；页面可打开 |

> **Node 用户升级前必做**：新版停机最多需要 80 秒收尾，升级重启会触发停机。若容器仍是默认 10 秒，升级中正在发的通知可能丢失。先按 [停止宽限与部署配置](07-停止宽限与部署配置.md) 配好 ≥90s 再重启。

## 二、如何确认当前版本

打开管理页，拉到**最底部**，页脚显示版本号。

- 当前源码版本 **`v1.1.0`** 已固化至 `main`（`43aaecf`）；**尚未创建 GitHub Release / 未打 tag / 未部署**。
- 一键部署按钮拉的是公开仓库 `main` 分支（当前 `43aaecf`）。**一律以页脚数字为准**，别按文档标题猜版本。

## 三、如何备份

| 备份什么 | 怎么做 |
|---|---|
| 消息内容（最简单） | 右键任意消息（手机长按）→ 导出 CSV / 导出 JSON，按当前筛选导出 |
| 整个数据库 | Cloudflare D1：控制台导出；Turso：`turso db shell <库名> .dump > backup.sql`；本地 SQLite：**先停容器**再复制 `SQLITE_PATH` 指向的 `.db` 文件 |
| 配置 | 通知渠道凭据与业务参数在数据库 `settings` 表里，已含在数据库备份中；登录密码与会话密钥**只在环境变量里**，另存到密码管理器 |

> CSV / JSON 只是**消息内容**，不含设备、令牌、设置，**不能**用它一键还原整个站点。

## 四、如何恢复

1. 重新部署同一版本代码；2. 准备空库/空目录，启动后 `ensureSchema` 自动建表；3. 导入备份（Turso：`turso db shell <库名> < backup.sql`；SQLite：用备份覆盖 `SQLITE_PATH`）；4. 重新填好环境变量；5. 打开管理页确认历史消息出现。

## 五、升级失败怎么办

| 现象 | 先做这个 | 仍不行 |
|---|---|---|
| 页面打不开 / 502 | 看部署平台日志，确认部署成功、环境变量还在 | 按 [UPGRADE 第五节](../UPGRADE.md) 重新部署旧代码 |
| 页面打开但空白 / 无数据 | 确认数据库凭据没变；看设置 → 统计 →「库结构自愈」 | 手动执行 `schema.sql`（幂等，重复执行安全） |
| 收不到消息 | 确认推送端 token 没变、`RECEIVE_TOKEN` 仍在、`DISABLE_RECEIVE_TOKEN` 没被误设 | [常见问题 · 收不到消息](05-常见问题.md#收不到消息) |
| 升级后通知不发了 | 检查设置中心通知总开关与渠道凭据 | 删除对应 `notify.*` 键回退到环境变量兜底 |

**回退永远安全的前提**：`RECEIVE_TOKEN` 一直保留着，旧代码只认它；回退前**不要**设置 `DISABLE_RECEIVE_TOKEN="true"`。

## 六、升级时不需要做的事

- 不需要手动执行任何 SQL（六平台都有运行时自愈）；
- 不需要改推送端（URL、token、脚本原样可用）；
- 不需要重新配置通知环境变量（数据库无对应键时自动兜底）；
- 不需要重建数据库。
