> 每一篇都先告诉你「点哪里、填什么」，再告诉你「怎么算成功」；看不懂的术语一律放在最后解释。

**当前版本状态**：源码 `v1.1.0` 已固化至 `main`（`43aaecf`）；**尚未创建 GitHub Release、未打 tag、未部署**，六平台真实运行验证 0/6。管理页最底部的页脚会显示你实际部署的版本号，请以它为准。

## 三、部署方式能力速览（不夸大）

| 平台 | 有没有官方部署按钮 | 点完还要做什么 | 详细指南 |
|---|---|---|---|
| **Cloudflare**（推荐新手） | ✅ 有 | 填 `RECEIVE_TOKEN` 等密钥；**建表由应用首次请求自动完成，不是按钮做的** | [指南](03-平台部署/01-Cloudflare.md) |
| Vercel | ✅ 有 | 先建 Turso 数据库、填 3 个环境变量、执行建表 | [指南](03-平台部署/02-Vercel.md) |
| Netlify | ✅ 有 | 先建 Turso、填 Base directory、填环境变量、执行建表 | [指南](03-平台部署/03-Netlify.md) |
| Deno Deploy | 平台有，本项目**未提供/未验证** | 走 Git 导入 + 控制台补环境变量 | [指南](03-平台部署/04-DenoDeploy.md) |
| 腾讯 EdgeOne Makers | 平台有，本项目**未提供/未验证** | Git 导入 + 手动配置；注意国内备案与预览链接有效期 | [指南](03-平台部署/05-EdgeOne.md) |
| Node / Docker 自托管 | ❌ **没有一键部署** | 全程手动，并且**必须配置 ≥90 秒停止宽限** | [指南](03-平台部署/06-Node自托管.md) |

> **没有任何一个平台可以「点一下就完全不用管」**。五个 Serverless 平台的按钮都属于「模板部署」：能帮你把代码变成运行中的应用，但密钥、外部数据库仍然要你自己填。完整依据（含官方 URL 与核实日期）见 [部署能力矩阵](10-部署能力矩阵.md)。

> **版本提示**：部署按钮拉取的是公开仓库 `main` 分支，当前已固化 `v1.1.0`（`43aaecf`）；仍以管理页页脚版本号为准。

## 四、哪些是「本地验证」，哪些是「生产配置」

这个区别很重要，请别混淆：

- **项目已验证（本地）**：850 项自动化测试全部通过；Node 停机流程在 **WSL2 + Docker 本地环境**用真实 `docker stop` 信号做过五组验证（含 25 秒长轮询、后台通知、SQLite 关闭顺序、超时记录）。这些**证明代码行为正确**。
- **必须由你完成（生产）**：容器 / 服务的停止宽限 ≥90 秒、密钥、数据库建表、域名与备案。项目代码和 `Dockerfile` 里的说明**不能**替你完成。
- **尚未验证**：五个 Serverless 平台的真实部署、真机浏览器兼容矩阵、公开仓库 `main` 分支与本地工作区的一致性。文档里凡涉及这些，都会明确标注，不会含糊承诺。
