# 使用指南

> 假设你已经按 [快速开始](02-快速开始.md) 部署好并看到第一条消息。

## 一、如何接入

### 手机短信（安卓）

1. 手机安装 **SmsForwarder**（或同类转发 App）。
2. 在 App 里新建一个「发送通道」，类型选 Webhook / HTTP。
3. 填地址：`https://你的域名/api/receive?token=你的RECEIVE_TOKEN`。
4. 按 [多平台接入部署指南](../多平台接入部署指南.md) 填消息模板。
5. 让手机保持后台运行：见 [安卓保活指南](../安卓SF保活指南.md)。

> **推荐用请求头带 token**：`X-Receive-Token: 你的密钥`，比放在网址里更安全（不会进访问日志/浏览器历史）。`?token=` 只是为了兼容 SmsForwarder 类客户端。

### 任意设备 / 脚本（通用推送）

```
POST https://你的域名/api/push?token=你的RECEIVE_TOKEN
{"source":"notify","sender":"demo","content":"一条通知"}
```

返回 `{"success":true,...}` 表示已入库；一模一样的内容再发一次会返回 `duplicated:true`，**这是正常的去重**，不会重复转发。

### 接入令牌（可选但推荐）

管理页 → **设置 → 安全 → 接入令牌**：可以为每台设备建独立令牌，支持备注、有效期、单设备吊销/轮换。库里只存哈希，**明文只显示一次，立即复制**。全部设备切到命名令牌后，可设 `DISABLE_RECEIVE_TOKEN="true"` 停用环境变量兜底。

## 二、如何接收消息

| 想做的事 | 在哪操作 |
|---|---|
| 看新消息 | 打开管理页即可，页面通过长轮询**自动刷新**，不用手动刷新 |
| 找某条消息 | 顶部搜索框输关键词；可按来源（短信 / 通知 / 自定义）、今天 / 近 7 天 / 近 30 天筛选 |
| 看全文 | 点消息卡片打开详情（列表默认只显示两行摘要） |
| 复制验证码 | 卡片顶部验证码胶囊，点一下复制；失败会明确报错，不会假装成功 |
| 收藏 / 未读 | 星标置顶、未读筛选、打开详情自动标记已读 |
| 多选 / 导出 | **右键任意消息**（手机端**长按**）进入批量选择，才有删除、清空、导出 CSV/JSON |

> 多选栏默认是隐藏的，这是设计如此。当前版本界面上没有常驻的「选择 / 导出」按钮，已记录在 [界面交互问题清单](08-界面交互问题清单.md)（B-2），属待批准改进项。

## 三、如何管理设备

右侧栏列出设备与最近接收时间；点标签旁的 **✎** 重命名、**⇄** 把消息合并到另一台设备、**×** 删除空标签。合并/删除是不可逆操作，界面会二次确认，**建议先导出备份**。

## 四、如何配置通知

管理页右上角 **⚙ 设置 → 通知**：

1. 打开总开关，勾选要转发的消息类型（验证码 / 短信 / 通知）。
2. 点 **添加推送**，选渠道（飞书 / 企微 / 钉钉 / Telegram / Server酱 / PushPlus / Bark / ntfy / Gotify / 邮件 / 自定义 Webhook）。
3. 填渠道要求的凭据（每个字段都有「去哪里拿」的说明），一个渠道可以配**多个独立目标**（比如两个飞书群）。
4. **保存** → 点 **发送测试通知** → **去对应群/邮箱确认是否收到**。

> 「测试通知已发送」只表示请求发出去了，**不等于对方已收到**。没收到时回到渠道配置检查凭据，再看下面的「发送失败」。

## 五、如何查看状态

| 看什么 | 在哪 |
|---|---|
| 消息统计 / 来源分布 / 近 7 天 | 右侧栏统计面板、设置里的「统计」 |
| 数据库结构是否正常 | 设置 → 「统计」弹窗底部「库结构自愈：正常（时间）」 |
| 当前版本 | 管理页最底部页脚 |
| 通知发送失败 | 部署平台的运行日志（本项目记录脱敏后的结构化日志） |

## 发送失败

按这个顺序查：

1. **凭据是否正确**：Webhook 地址 / Token 有没有复制全、有没有过期。敏感字段在页面里只显示「已配置 ••••」，留空保存不会清空旧值，要勾选「清除」才会移除。
2. **是否先保存了**：测试按钮用的是**已保存**的配置，改完必须先点保存。
3. **渠道是否启用**：总开关、消息类型、目标开关三层都要是「开」。
4. **是否被重试耗尽**：设置里的重试次数 0–3，单渠道每次最多 10 秒；多个渠道是**并行**的，一个失败不影响其他。
5. **是否部署到了停机窗口**：Node 自托管若停止宽限没配好，重启时后台通知会被杀掉 —— 见 [停止宽限与部署配置](07-停止宽限与部署配置.md)。

> **明确边界**：后台通知有 45 秒等待上限，超时会记 `background_task_timeout`，**不会补发、不会记为成功**。消息本身已入库不会丢，丢的只是这条转发通知。

## 六、导出与备份

右键（手机长按）消息进入批量选择 → **导出 CSV / 导出 JSON**，按当前筛选导出。

> CSV/JSON 只是**消息内容**的留存，不含设备、令牌、设置，不能靠它还原整个站点。完整数据库备份见 [更新与维护](09-更新与维护.md)。

## 七、日常设置

- **会话时长**：设置 → 登录与会话，可按浏览器单独设（5–43200 分钟）。
- **界面语言**：设置 → 界面语言，内置 9 种语言。
- **主题 / 免打扰 / 声音 / 每页条数**：都在设置中心，按分组保存/取消/恢复默认。
- **并发编辑保护**：两个会话同时改设置，后保存的会收到「设置已被其他会话修改」，重新打开再保存即可，不会出现半套配置。
