# 常见问题（用大白话）

> 按「你看到的现象」找，不用从头读。每条都先给**马上能试的动作**，再解释原因。

## 收不到消息

按顺序试，*通常第 1、2 条就能解决*：

| # | 检查 | 怎么做 |
|---|---|---|
| 1 | 推送端地址对不对 | 域名有没有写错、是不是 `https`；路径是 `/api/receive`（短信）或 `/api/push`（通用） |
| 2 | token 对不对 | 和部署平台里 `RECEIVE_TOKEN`（或你建的命名令牌）完全一致；令牌有没有过期/被吊销；`DISABLE_RECEIVE_TOKEN` 有没有被误设成 `true`（**注意**：该开关已在 v1.1.0（P1）修复，六个平台都会停用兜底，见下方「已知不一致」） |
| 3 | 手机端还在后台吗 | 安卓省电策略会杀掉转发 App，按 [安卓保活指南](../安卓SF保活指南.md) 设置 |
| 4 | 请求真的发出去了吗 | 看转发 App 的发送日志；有 `{"success":true}` 才是入库成功 |
| 5 | 是不是被去重了 | 完全一样的内容短时间内重复发会返回 `duplicated:true`，**这是正常的**，不会重复入库/转发 |
| 6 | 筛选条件是不是太窄 | 把时间范围切回「近 30 天」、清空关键词、关掉「仅未读/仅收藏」 |
| 7 | 数据库是否正常 | 设置 → 统计 → 底部「库结构自愈」是否显示「正常」；异常时会给出原因摘要 |
| 8 | 是不是 429 / 401 | 429 = 同一 IP 每分钟写入超过 120 次，等一分钟；401/403 = token 无效，回第 2 条 |

> 返回 401/403 时先别改数据库：`/api/receive` 和 `/api/push` **不受登录开关影响**，一定是 token 的问题。

## 部署失败

| 现象 | 先试这个 |
|---|---|
| 按钮点了没反应 / 仓库报错 | 确认仓库是 **public**、在 `github.com`/`gitlab.com`；Cloudflare 按钮只支持 Workers，不支持 Pages；monorepo 支持不完整 |
| 构建失败 | 本项目**零构建**：Vercel Framework Preset 选 `Other`、Build Command 留空；Netlify 的 Base directory 填 `platforms/netlify`；EdgeOne 根目录填 `platforms/edgeone` |
| 页面 502 / 打不开 | 看部署平台构建与运行日志，确认部署成功、环境变量还在 |
| 页面打开但空白 / 无数据 | 数据库凭据是否正确、是否已建表；Turso 的 Token 只显示一次，抄错只能重新生成 |
| 环境变量改了不生效 | Vercel / Netlify / EdgeOne 改完变量要**重新部署** |
| 预览链接 401（EdgeOne） | 预览链接 3 小时过期，回控制台刷新；国内长期用需绑自定义域名 + 备案 |
| 免费额度用完 | 看平台控制台用量概览；Netlify 现行 Free 是每月 300 credits，用完暂停到下周期 |

> 部署平台自己的能力限制（免费额度、备案、地区）见 [部署能力矩阵](10-部署能力矩阵.md)，那里附了官方出处。

## 为什么需要 Token

Token（本项目叫 `RECEIVE_TOKEN`）是一把**钥匙**：只有带着正确钥匙的请求才能往你的页面里写消息。没有它，任何知道网址的人都能往里灌垃圾消息。

- 它**只用于推送接口**，和「管理页登录密码」是两回事；
- 建议用 `X-Receive-Token` 请求头携带（不进访问日志、浏览器历史）；`?token=` 只是兼容老客户端；
- 可以在管理页给每台设备建**独立命名令牌**，丢了一台设备就吊销那一个，不用换全局密钥。

## 为什么数据库需要初始化

数据库里得先有「放消息的表格」，应用才能存东西。本项目会在**第一次请求**时自动建表、补列、建索引（`ensureSchema`），所以大多数情况下你**什么都不用做**。

但下面两种情况建议手动执行一次 `schema.sql`：

- 外部 Turso 数据库（Vercel / Netlify / Deno / EdgeOne）——按钮不会替你建表，手动执行更稳妥；
- 管理页「统计」里显示「库结构自愈：失败」——按 [升级指南](../UPGRADE.md) 第三节的兜底命令执行。

`schema.sql` 是幂等的（全部 `IF NOT EXISTS`），**重复执行安全**。

## 更换部署平台

六个平台的**接口路径、数据格式、管理页完全一样**，可以换：

1. 按 [平台部署总览](03-平台部署/README.md) 在新平台部署一份（先准备好新平台的数据库）。
2. 把旧平台的数据导过去：Cloudflare D1 在控制台导出 → Turso 用 `turso db import`；或直接用管理页导出 CSV/JSON 留存消息内容。
3. 把手机端和所有推送脚本里的**域名换成新地址**，token 保持不变（或换成新平台的命名令牌）。
4. 两边并行观察一两天，确认新平台收发正常。
5. 再停用旧平台。

> **注意**：CSV/JSON 导出只含消息内容，不含设备、令牌、设置；换平台后这些需要在新平台重新配置。

## 为什么通知发出去了却没收到

「测试通知已发送」只代表请求发出去了。请按 [使用指南 · 发送失败](04-使用指南.md#发送失败) 逐项检查；另外要理解一个明确边界：**后台通知有 45 秒等待上限，超时不会补发**，消息本身仍在页面里，只是那条转发可能遗漏。

## 版本号怎么看

管理页**最底部页脚**。当前源码版本 `v1.1.0`（RC2 候选）；目标 `v1.1.0` 尚未正式发布。一键部署按钮拉的是公开仓库 `main` 分支，可能比本地文档旧 —— **一律以页脚数字为准**，别按文档标题猜版本。

## 其他

| 问题 | 答案 |
|---|---|
| 一条消息最长多少 | 正文最多保存 8000 字符，超出部分截断 |
| 为什么有 `{{XXX}}` 这种奇怪文字 | 自定义标签里出现字面 `{{` 时系统会置空并回退到 SIM 号；直接在模板的 `name` 字段填名字即可 |
| 令牌有效期怎么算 | 自定义日期按 **UTC** 计算，`YYYY-MM-DD` 表示当天 23:59:59 UTC（= 北京时间次日 07:59:59） |
| 忘了登录密码 | 密码是你自己在部署平台 `ADMIN_PASSWORD` 里设的，去平台环境变量里查看/重置；系统不会用别的派生值放行 |

## 已知不一致（诚实告知，暂不影响使用）

> **状态更新（2026-11-10，v1.1.0 / P1）：** `DISABLE_RECEIVE_TOKEN` 的跨平台透传不一致**已修复**。该变量已纳入 32→33 项 `ENV_KEYS` 白名单，六个移植入口的 `buildEnv()` 均会透传，停用 `RECEIVE_TOKEN` 兜底在 **Cloudflare / Vercel / Netlify / Deno / EdgeOne / Node 全部六个平台**生效。以下为历史核对记录，保留以说明来龙去脉。

**历史记录：2026-11-09 核实，该开关曾只在 Cloudflare 上生效。**

- 它本来的作用是：当你给每台设备都建好独立命名令牌后，把「部署时的全局密钥」停用，只认独立令牌。
- 2026-11-09 核实：业务代码会读这个变量（`src/worker.js:8246`），但它**不在 32 项 `ENV_KEYS` 白名单**里，Vercel / Netlify / Deno / EdgeOne / Node 五个入口的 `buildEnv()` 只按白名单透传，所以这些平台上**设置了也不会停用全局密钥**。
- 2026-11-10 修复：在 `platforms/gen_app.py` 的 `ENV_KEYS` 中加入 `DISABLE_RECEIVE_TOKEN`，重新运行生成器把白名单同步到全部六个入口（Cloudflare 直接传完整 `env`，本就生效）；并新增 `tests/p1-auth.mjs` 跨平台透传与行为测试（23/0）。默认（未设置）仍保留兜底启用，仅 `"true"`（大小写/空白不敏感）停用；库内命名令牌优先级高于该开关，不受影响。
- **对你的影响（修复后）**：在任意平台上，设 `DISABLE_RECEIVE_TOKEN="true"` 都会停用全局 `RECEIVE_TOKEN` 兜底，只认库内命名令牌；命名令牌的单设备吊销/轮换功能**始终可用**。仍请妥善保管 `RECEIVE_TOKEN`。
