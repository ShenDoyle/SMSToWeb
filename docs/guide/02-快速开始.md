# 快速开始：从零到收到第一条消息

> 目标：**部署好 → 设置好凭据 → 发出一条测试消息 → 在网页上看到它**。
> 全程跟着「先做什么、填什么、怎么算成功」走，看不懂的名词先跳过，最后有解释。

---

## 开始前，只需要准备 3 样东西

| 需要准备 | 具体要求 | 没有怎么办 |
|---|---|---|
| ① 一个平台账号 | 推荐 Cloudflare（免费、无需服务器）；也可以用 Vercel / Netlify / Deno Deploy / EdgeOne | 点对应平台注册页，用 GitHub 账号登录最快 |
| ② 一个 GitHub 账号 | 部署按钮会把代码克隆到你自己的仓库 | [github.com](https://github.com) 免费注册 |
| ③ 一个自己编的长随机串 | 当作「推送密钥」，叫 `RECEIVE_TOKEN` | 用密码管理器生成 32 位随机字符串；**不要用示例值** |

**不需要买服务器**（除非你选 Node 自托管）。**不需要买域名**：平台会给你一个免费地址（如 `xxx.workers.dev`）；想用自己的域名可以以后再绑。

## 第 1 步：选一个部署平台

| 你的情况 | 选这个 | 大约要填几项 | 详细步骤 |
|---|---|---|---|
| **第一次用、想最省事** | **Cloudflare** | 1 项必填（+2 项可选） | [Cloudflare 指南](03-平台部署/01-Cloudflare.md) |
| 已有 Vercel / Netlify 账号 | Vercel / Netlify | 3 项 + 建一个 Turso 数据库 | [Vercel](03-平台部署/02-Vercel.md) / [Netlify](03-平台部署/03-Netlify.md) |
| 想用 Deno / 腾讯 EdgeOne | Deno Deploy / EdgeOne | 3 项 + 建 Turso 数据库 | [Deno](03-平台部署/04-DenoDeploy.md) / [EdgeOne](03-平台部署/05-EdgeOne.md) |
| **已有服务器，想完全自己控制** | Node / Docker | 全部手动 + **必做停止宽限** | [Node 自托管](03-平台部署/06-Node自托管.md) + [停止宽限配置](07-停止宽限与部署配置.md) |

> 不确定就选 **Cloudflare**：它是唯一「按钮会自动创建并绑定数据库」的平台，填的东西最少。
> 但请记住：**按钮不等于全部完成**，密钥仍然要你填；建表是应用首次请求自动做的，不是按钮做的。详见 [部署能力矩阵](10-部署能力矩阵.md)。

## 第 2 步：完成部署

打开你选的[平台指南](03-平台部署/README.md)，按里面的「点击步骤」逐步操作。每个指南都写明了：

- 按钮/入口在哪（具体页面与菜单）
- 每个字段填什么（含示例值）
- **成功标志**（看到什么才算这一步完成）
- 常见错误与解决办法

**完成标志（通用）**：在浏览器打开平台给你的地址，能看到 SMSToWeb 管理页（哪怕现在是空的、没有消息，也算成功）。

> 如果打不开，别急着重装，先去 [常见问题 · 部署失败](05-常见问题.md#部署失败)。

---

## 第 3 步：设置访问凭据（重要，别跳过）

**为什么**：管理页里会有短信验证码等敏感内容。默认**不开启登录**，任何知道网址的人都能看。这一步决定谁能访问。

| 字段 | 在哪填 | 填什么 | 示例 |
|---|---|---|---|
| `RECEIVE_TOKEN` | 部署平台的「环境变量 / Secrets」设置页（Cloudflare 在按钮的设置页就会问） | 自己编的长随机串，手机端和脚本要用它 | `tK8mQ2xV7pL...`（32 位以上） |
| `ENABLE_AUTH` | 同上 | 填 `true` = 打开登录（**强烈建议**） | `true` |
| `ADMIN_PASSWORD` | 同上 | 管理页登录密码，自己编 | 用密码管理器生成 |
| `SESSION_SECRET` | 同上 | **另一个**独立的高熵随机串（≥32 位），**不能和密码相同** | 另生成一个 |

> 开启登录时，`ADMIN_PASSWORD` 和 `SESSION_SECRET` 缺一不可；漏配时系统会**拒绝登录和管理接口**（不会偷偷放行），这是安全设计，不是故障。
> 这三个值各平台必须分别设置、不要复用；也不要写进 GitHub 仓库文件里。

**完成标志**：打开管理页时出现登录框，用 `ADMIN_PASSWORD` 能登录进去。

## 第 4 步：发出第一条测试消息

**目标**：让一条消息出现在管理页列表里。

**方式 A（推荐，最贴近真实使用）**：在安卓手机装 SmsForwarder，按 [多平台接入部署指南](../多平台接入部署指南.md) 配置转发地址，然后给自己发一条短信或让任意 App 弹一条通知。

**方式 B（最快验证，需要一条命令）**：在你自己电脑的终端里执行（把域名和 token 换成你的）：

```bash
curl "https://你的域名/api/push?token=你的RECEIVE_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"source":"notify","sender":"deploy-test","content":"第一条测试消息"}'
```

看到 `{"success":true,...}` 说明消息已经存进数据库了。再发一条一模一样的会返回 `duplicated:true`，这是正常的去重行为。

> **诚实说明**：当前版本**网页里没有「给自己发一条测试消息」的按钮**。设置中心里的「发送测试通知」只测试**通知转发渠道**（飞书/微信等），不会往管理页写一条消息。这个缺口已记录在 [界面交互问题清单](08-界面交互问题清单.md)（B-6），属于需要审批后才能改的功能，本轮没有擅自增加。

## 第 5 步：确认收到（成功标志）

| 检查项 | 成功是什么样 |
|---|---|
| 管理页列表 | 出现刚才那条「第一条测试消息」 |
| 页面自动刷新 | 新消息会自己出现，不需要手动刷新 |
| 手机端 | 390px 宽度下不横向溢出、按钮能点 |
| 页脚版本号 | 显示一个具体版本号（例如 `v1.1.0`） |

**看到消息 = 完整链路成功**。这时可以：

- 去 [使用指南](04-使用指南.md) 配置通知转发、来源筛选、导出备份；
- 去 [常见问题](05-常见问题.md) 处理「收不到消息」等后续问题。

---

## 第 6 步（可选但建议）：开启通知转发

管理页右上角 **⚙ 设置 → 通知 → 添加推送**，选一个渠道（如飞书群机器人），把机器人提供的 Webhook 地址粘进去 → **保存** → 点 **发送测试通知** → **去对应的群/邮箱看有没有收到**。

> 界面提示「测试通知已发送」只代表**请求发出去了**，不等于对方已收到。请务必去渠道里确认，这是当前版本判断成功的唯一可靠方式。

## 名词解释（看不懂再回来）

- **环境变量 / Secret**：部署平台提供的一张「配置表」，填 `名称 = 值`。应用启动时读取，用来放密码和密钥，避免写进代码。
- **Turso**：一个免费的 SQLite 兼容云端数据库。除 Cloudflare 外，其余平台需要你先去 [turso.tech](https://turso.tech) 建一个，再把地址和令牌填进配置表。
- **建表**：数据库里先要有存放消息的「表格」。本项目会在**第一次请求**时自动建好，通常不需要你手动执行 SQL。
- **Webhook**：一个网址，别人往这个网址发数据，你的群/应用就能收到消息。
