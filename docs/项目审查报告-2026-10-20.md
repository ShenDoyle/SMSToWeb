## 三、问题清单（按优先级）

### P1-1 · 设备标签计数把软删除消息算进去（功能 Bug，已复现实锤）

- **位置**：`src/worker.js` `handleListDevices()`（约 L902-917）
- **现象**（实测）：设备 2 条消息全部软删除后，`/api/devices` 仍返回 `msg_count = 2`：
  1. 设备 tab 显示幻影计数「测试机 (2)」，「全部」tab 总数同步虚高；
  2. 前端**只在 `!d.msg_count` 时才渲染「×」删除按钮** → 消息删完后最多 7 天内（等 cron 清理软删记录）无法从 UI 删除该标签；
  3. 后端 `DELETE /api/devices/:id` 实际允许删（返回 200）——前后端行为不一致；`last_at` 同样包含已删消息。
- **修复提案**（一行 SQL）：LEFT JOIN 条件加 `AND m.deleted_at IS NULL`，即
  `LEFT JOIN messages m ON m.device_id = d.id AND m.deleted_at IS NULL`
- **回归测试**：软删除该设备全部消息 → `GET /api/devices` 该设备 `msg_count === 0`。
- **影响端**：改 src/worker.js 后需 `python platforms/gen_app.py` 全平台同步 + 跑测试。

### P2-2 · Cloudflare 主版本缺 `/api/cron` HTTP 触发路由（功能缺口 + 文档不实）

- **现象**：5 个移植平台入口均路由 `/api/cron?token=`（token 鉴权）；**Cloudflare worker.js 的 fetch 路由里没有 `/api/cron`**，外部定时器打过去会 404。而 `platforms/README.md` L95 明确把 `/api/cron` 列入「API 路径全平台一致」清单，README 主文件 L52 也宣传「无平台 cron 的部署，用任意定时器请求 GET /api/cron」。
- **修复提案**（二选一）：
  - A（推荐）：`src/worker.js` 路由加 `/api/cron`（复用 `handleCron` + safeEqual token 校验，约 10 行；注意 `handleCronRequest` 目前只存在于 gen_app 生成的 `shared/app.js` 尾部，CF 侧需在 worker.js 内实现或让 gen_app 一并注入）；
  - B：文档限定「/api/cron 适用于五个移植平台；Cloudflare 用平台 cron」。
- **注意**：选 A 时 Cloudflare 的 cron trigger 与外部触发可并存，无冲突。

### P2-3 · 响应缺安全响应头（加固项）

- **现象**：全部响应未设 `X-Content-Type-Options: nosniff`、`X-Frame-Options`/`frame-ancestors`、`Referrer-Policy`。管理页可被 iframe 嵌套（结合默认免登录的部署 = 点击劫持面），manifest/sw 的 `Content-Type` 也无 nosniff 保护。
- **修复提案**：在 `json()` 与三处 `new Response`（页面/manifest/sw）统一加 `X-Content-Type-Options: nosniff` + `Referrer-Policy: no-referrer` + `X-Frame-Options: DENY`（管理页无框架需求）。CSP 因内联 script/style 需 nonce 或 `'unsafe-inline'`，收益有限，可不做或在报告中记录取舍。

### P2-4 · 限速/登录锁定可被 XFF 伪造绕过（软限制的已知边界，建议补强）

- **位置**：`clientIp()`（L164-168）：取 `CF-Connecting-IP` → **XFF 第一段** → "unknown"。
- **现象**：非 CF 平台上 XFF 左段是客户端自带值、可任意伪造 → 攻击者轮换 XFF 即可同时绕过「登录 5 次锁定」和「写入 120 次/分」。CF 上有 `CF-Connecting-IP` 不受影响。
- **修复提案**：非 CF 平台改取 XFF **最后一段**（平台边缘追加、客户端伪造不了），或按平台信任头（Netlify `x-real-ip` 等）优先。代码注释已自称「尽力而为的软限制」，但把默认取第一段改成取末段是零成本补强。
