# SMSToWeb 多平台接入部署指南

> 适配版本：**v1.0.3**。自 v1.0.3 起，通知渠道与高频业务参数改为**数据库优先**，在管理页「设置 → 通知与业务设置」配置即可；下文出现的旧环境变量仍然兼容（数据库没有对应键时才读取），不需要为升级改任何变量。

本系统由两部分组成：**接收端**（各平台的推送客户端）+ **云端网关**（六个平台任选其一：Cloudflare / Vercel / Deno / Netlify / EdgeOne Makers / Docker 自托管，见 [platforms/README.md](../platforms/README.md)，接入方式完全相同）。
短信只是接入路径之一——任何能发 HTTP 请求的设备/脚本，都能把通知推到同一个网页里查看。

```
安卓(SmsForwarder)──┐  短信+应用通知
iOS(快捷指令)───────┤
Linux(curl/ntfy)────┼──→ POST /api/receive（短信）或 /api/push（通用通知）
Windows(PowerShell)─┤         │
macOS(快捷指令)─────┘         ▼
                        Cloudflare Worker ──→ D1 存储 ──→ 统一网页（来源筛选）
                              │
                              └──（可选）多渠道通知 → 飞书/企微/钉钉/TG/Bark/邮件…
```

## 一、云端配置（Cloudflare 侧）

### 1. 变量与密钥

部署 Worker 后，在 **Workers 和 Pages → sms-gateway → 设置 → 变量和机密** 中配置：

| 名称 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `RECEIVE_TOKEN` | 密钥 | 是 | 推送鉴权令牌，自己编一串随机字符（不要用示例值） |
| `ADMIN_PASSWORD` | 密钥 | 开登录时配置 | 管理页登录密码，建议强密码；漏配时管理接口一律拒绝访问（配置缺失不放行），并输出告警 |
| `ENABLE_AUTH` | 文本 | 否 | `"true"` 开启登录（**安全强烈建议**：管理页承载短信验证码等敏感内容，默认免登录等于对任何知道域名的人开放）；`"false"` 或不设为免登录 |
| `FEISHU_WEBHOOK` | 文本 | 否 | 飞书群机器人 Webhook，配置后新消息自动转发飞书群（签名校验另配 `FEISHU_SECRET`） |
| `FEISHU_SECRET` | 密钥 | 否 | 仅当飞书机器人安全设置选「签名校验」时配置，程序自动计算签名 |
| `WECOM_WEBHOOK` | 文本 | 否 | 企业微信群机器人 Webhook |
| `DINGTALK_WEBHOOK` | 文本 | 否 | 钉钉群机器人 Webhook（加签安全设置需另配 `DINGTALK_SECRET`） |
| `SERVERCHAN_SENDKEY` | 文本 | 否 | Server酱 SendKey（微信推送） |
| `PUSHPLUS_TOKEN` | 文本 | 否 | PushPlus 令牌（微信推送） |
| `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID` | 文本 | 否 | Telegram Bot 令牌 + 会话/群 ID |
| `BARK_DEVICE_KEY` | 文本 | 否 | Bark 设备 Key（自建服务器另配 `BARK_URL`，默认官方） |
| `NTFY_URL` | 文本 | 否 | ntfy 完整主题 URL，如 `https://ntfy.sh/my-sms`（受保护主题另配 `NTFY_TOKEN`） |
| `NTFY_TOKEN` | 文本 | 否 | ntfy 受保护主题访问令牌：Access Token 直接填（走 Bearer）；自建服务器按 `user:password` 填（走 Basic） |
| `GOTIFY_URL` + `GOTIFY_TOKEN` | 文本 | 否 | Gotify 服务器地址（不含 `/message`）+ 应用令牌 |
| `RESEND_API_KEY` + `MAIL_TO` | 文本 | 否 | 邮件（Resend API）；可选 `MAIL_FROM`，默认 `onboarding@resend.dev` |
| `GENERIC_WEBHOOKS` | 文本 | 否 | 通用 Webhook，逗号分隔多个 URL；可选 `GENERIC_WEBHOOK_TEMPLATE` 自定义请求体、`GENERIC_WEBHOOK_HEADERS` 自定义请求头 |
| `GENERIC_WEBHOOK_HEADERS` | 文本 | 否 | 通用 Webhook 自定义请求头，JSON 对象字符串，如 `{"Authorization":"Bearer xxx"}` |
| `NOTIFY_LINK` | 文本 | 否 | 管理页首页地址；配置后所有通知渠道附「打开管理页」入口（飞书按钮、各渠道链接行、Bark url、ntfy click 等），未配置自动省略 |
| `SESSION_SECRET` | Secret | 开启登录时必须 | 登录会话签名密钥：**高熵随机值（建议 ≥32 位随机字符串），与管理密码完全独立**；CF 与 EO（及各平台）分别配置独立值，严禁提交 Git 或复用密码。缺失时登录与鉴权安全失败（登录 500、管理接口 401），不回退密码派生。轮换后所有旧会话立即失效重新登录；会话有效期默认 30 分钟（管理页「设置 → 会话时长」可调 5~43200，仅影响新签发会话），退出登录仅清浏览器 Cookie，已复制 Token 在 TTL 内仍可能有效 |
| `RETENTION_DAYS` | 文本 | 否 | 数据保留天数，默认 30，改完即时生效 |
| `WAIT_MAX_SECONDS` | 文本 | 否 | 长轮询 `/api/wait` 最长挂起秒数，默认 25（3–25）。**Netlify Functions 默认 10s 上限 → 建议填 `8`**；Vercel Edge 建议 `20`。前端遇失败会指数退避，不会打爆函数 |

> **关于上表的后半部分（v1.0.3 起）**
> `FEISHU_WEBHOOK` 到 `NOTIFY_LINK`、以及 `RETENTION_DAYS`，都已成为**兼容旧部署的兜底变量**：推荐在管理页「设置 → 通知设置 / 业务设置」里配置（支持渠道启停、凭据脱敏显示、逐渠道测试、保存后回读校验）。
> 数据库里没有对应键时才读取这些环境变量；在设置页保存后数据库值优先；留空保存不会清空已有凭据，勾选「清除」才会移除并遮蔽同名变量。
> `ADMIN_PASSWORD`、`SESSION_SECRET`、`RECEIVE_TOKEN`、`ENABLE_AUTH`、`DISABLE_RECEIVE_TOKEN` 是安全边界，**始终只走环境变量**，设置页不提供修改。

> **两条安全提示**
> 1. 管理页登录（`ENABLE_AUTH="true"`）强烈建议开启，并配强密码 `ADMIN_PASSWORD`；登录接口已内置限速（同 IP 连续失败 5 次锁定 10 分钟），`/api/receive`、`/api/push` 每分钟写入超 120 次会返回 429（稍后自动恢复）。
> 2. 推送 token 兼容 `?token=` URL 传参（SmsForwarder 场景），token 会出现在 URL 中、可能进平台访问日志；介意者改用 POST + `Authorization: Bearer <RECEIVE_TOKEN>` 请求头传递，两种方式都支持。

### 2. 通知转发渠道（可选，配置哪个转发哪个）

**v1.0.3 推荐路径**：登录管理页 → 设置 → **通知设置** → 找到对应渠道 → 填入凭据 → 打开「启用」→ 点「发送测试通知」确认能收到 → 保存。页面上还有总开关、转发类型（验证码 / 短信 / 设备通知）、失败重试次数（0~3）与管理页跳转链接。
凭据只以「已配置 ••••末4位」显示，不会回显完整值；留空保存=沿用旧值，勾选「清除」才删除。
已有旧环境变量的部署，可点同页「从环境变量导入」把缺失项一次性搬进数据库（不覆盖已有值）；**不导入也没关系**，旧变量继续生效。

旧路径（仍然有效）：在部署平台的「环境变量 / Variables」页面添加对应变量即可启用，**全部不配置则不转发，不影响消息入库与网页查看**。
多渠道并发转发，单个渠道失败不影响其他渠道（失败会按设置页的重试次数重试）；重复消息（`duplicated:true`）不会重复转发。

> 下面每条渠道说明里的「填入变量」，在设置页里对应的是**同名字段的输入框**（例如 `FEISHU_WEBHOOK` → 飞书渠道的「Webhook」字段）；两者配置含义完全一致，推荐用设置页。

设置页字段与旧环境变量、数据库键的对应关系（字段名以接口为准，页面标签为中文）：

| 渠道 | 设置页字段 | 数据库键 | 旧环境变量（兼容兜底） |
|---|---|---|---|
| 全局规则 | 总开关 / 转发类型 / 失败重试 / 跳转链接 | `notify.enabled` / `notify.types` / `notify.retry` / `notify.link` | 无（旧版行为固定；`notify.link` 对应 `NOTIFY_LINK`） |
| 飞书 | Webhook / 签名密钥 | `notify.feishu.webhook` / `.secret` | `FEISHU_WEBHOOK` / `FEISHU_SECRET` |
| 企业微信 | Webhook | `notify.wecom.webhook` | `WECOM_WEBHOOK` |
| 钉钉 | Webhook / 加签密钥 | `notify.dingtalk.webhook` / `.secret` | `DINGTALK_WEBHOOK` / `DINGTALK_SECRET` |
| Server酱 | SendKey | `notify.serverchan.sendkey` | `SERVERCHAN_SENDKEY` |
| PushPlus | Token | `notify.pushplus.token` | `PUSHPLUS_TOKEN` |
| Telegram | Bot Token / Chat ID | `notify.telegram.bot_token` / `.chat_id` | `TELEGRAM_BOT_TOKEN` / `TELEGRAM_CHAT_ID` |
| Bark | Device Key / 服务地址 | `notify.bark.device_key` / `.url` | `BARK_DEVICE_KEY` / `BARK_URL` |
| ntfy | 服务地址 / Token | `notify.ntfy.url` / `.token` | `NTFY_URL` / `NTFY_TOKEN` |
| Gotify | 服务地址 / Token | `notify.gotify.url` / `.token` | `GOTIFY_URL` / `GOTIFY_TOKEN` |
| 邮件（Resend） | API Key / 收件人 / 发件人 | `notify.resend.api_key` / `.mail_to` / `.mail_from` | `RESEND_API_KEY` / `MAIL_TO` / `MAIL_FROM` |
| 通用 Webhook | 地址列表 / 请求体模板 / 请求头 | `notify.generic.urls` / `.template` / `.headers` | `GENERIC_WEBHOOKS` / `GENERIC_WEBHOOK_TEMPLATE` / `GENERIC_WEBHOOK_HEADERS` |

每个渠道另有 `notify.<渠道>.enabled` 控制启停（默认启用，与旧版“配置即启用”一致）。

通知按内容自动分**三态**渲染（全渠道一致）：检测到验证码 → **验证码提醒**（验证码进标题/卡片大字；Bark 通知一点即复制验证码，Bark 与 ntfy 提升优先级）；无验证码短信 → **新短信**；App/设备推送 → **设备通知**。设置页「跳转链接」（旧变量 `NOTIFY_LINK` 兼容）配置后，各渠道自动附「打开管理页」入口，未配置自动省略。

通用 Webhook 默认请求体为 JSON，新增 `type`（`verify`/`sms`/`notify`）与 `code`（识别出的验证码，未检出为空串）字段；`GENERIC_WEBHOOK_TEMPLATE` 模板占位符随之支持 `{{type}}`/`{{code}}`。

各渠道申请步骤：

**飞书群机器人** — `FEISHU_WEBHOOK`（可选 `FEISHU_SECRET`）
1. 飞书目标群 → 设置 → 群机器人 → 添加机器人 → **自定义机器人**
2. 取得 Webhook 地址，形如 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxxxxxx`，填入变量即可
3. 安全设置三选一：**自定义关键词**（推荐：关键词填 `短信` 等即可，无需其他配置）；**签名校验**（把密钥填入 `FEISHU_SECRET`，程序自动计算签名）；IP 白名单（Worker 出口 IP 不固定，勿选）

**企业微信群机器人** — `WECOM_WEBHOOK`
1. 企微目标群 → 右上角群设置 → 群机器人 → 添加机器人 → 新建
2. 复制 Webhook 地址，形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxxx`，填入变量即可

**钉钉群机器人** — `DINGTALK_WEBHOOK`（可选 `DINGTALK_SECRET`）
1. 钉钉目标群 → 群设置 → 智能群助手 → 添加机器人 → **自定义**（Webhook 接入）
2. 安全设置建议选 **加签**：把页面显示的密钥（SEC 开头）填入 `DINGTALK_SECRET`；不配则按无签直连
3. 复制 Webhook 地址（形如 `https://oapi.dingtalk.com/robot/send?access_token=xxxx`）填入 `DINGTALK_WEBHOOK`

**Server酱（微信推送）** — `SERVERCHAN_SENDKEY`
1. 打开 [sct.ftqq.com](https://sct.ftqq.com)，微信扫码登录
2. 首页复制 **SendKey**（形如 `SCTxxxxxxxxxxxx`），填入变量；消息推送到你的微信「方糖」服务号

**PushPlus（微信推送）** — `PUSHPLUS_TOKEN`
1. 打开 [pushplus.plus](https://www.pushplus.plus)，微信扫码登录
2. 首页复制 **token**，填入变量；关注公众号后即可在微信收到推送

**Telegram Bot** — `TELEGRAM_BOT_TOKEN` + `TELEGRAM_CHAT_ID`（两个都配置才生效）
1. TG 里找 [@BotFather](https://t.me/BotFather) → `/newbot` 按提示创建 → 得到 Bot Token（形如 `123456:ABC-xxx`）
2. 取 `chat_id`：先给你的 Bot 发一条消息，再浏览器打开 `https://api.telegram.org/bot<你的Token>/getUpdates`，在返回 JSON 里找 `chat.id`（群聊把 Bot 拉进群并发一条消息后同样可查到群 ID）
3. 两个值分别填入 `TELEGRAM_BOT_TOKEN` 与 `TELEGRAM_CHAT_ID`

**Bark（iOS 推送）** — `BARK_DEVICE_KEY`（可选 `BARK_URL`）
1. App Store 安装 [Bark](https://apps.apple.com/app/bark-customed-notifications/id1403753865)，打开 App 复制示例 URL 中的 Key 部分（`https://api.day.app/<这串就是Key>/...`）
2. Key 填入 `BARK_DEVICE_KEY`；自建服务器再配 `BARK_URL`（默认官方 `https://api.day.app`）

**ntfy（安卓/iOS/网页订阅）** — `NTFY_URL`（可选 `NTFY_TOKEN`）
1. 手机装 ntfy App（或用 [ntfy.sh](https://ntfy.sh) 网页），订阅一个自定义主题名（topic），如 `my-sms-9f2k`（名字越随机越私密）
2. `NTFY_URL` 填完整主题 URL：`https://ntfy.sh/my-sms-9f2k`（自建服务器填你的地址；支持反代子路径部署）
3. 主题开启访问控制时配 `NTFY_TOKEN`：Access Token（`tk_` 开头）直接填入；自建服务器按 `用户名:密码` 格式填入

**Gotify（自建推送服务）** — `GOTIFY_URL` + `GOTIFY_TOKEN`
1. 已自建 Gotify 的，网页登录 → **Apps** → 创建应用 → 复制 **Token**
2. `GOTIFY_URL` 填服务器地址（如 `https://push.example.com`，**不要带** `/message`），Token 填 `GOTIFY_TOKEN`

**邮件（Resend API）** — `RESEND_API_KEY` + `MAIL_TO`（可选 `MAIL_FROM`）
1. 打开 [resend.com](https://resend.com) 注册（免费额度每天 100 封、每月 3000 封）
2. **API Keys** → Create API Key，复制填入 `RESEND_API_KEY`
3. `MAIL_TO` 填收件邮箱（多个用逗号分隔）；`MAIL_FROM` 不填时默认 `onboarding@resend.dev`（该默认发件人只能发给你注册 Resend 的邮箱；要发给任意邮箱需在 Resend 验证自己的域名并配 `MAIL_FROM`）

**通用 Webhook / 第三方 API** — `GENERIC_WEBHOOKS`（可选 `GENERIC_WEBHOOK_TEMPLATE` / `GENERIC_WEBHOOK_HEADERS`）
1. `GENERIC_WEBHOOKS` 填一个或多个 URL（**逗号分隔**）。默认 POST JSON：

```json
{"title":"【短信】13800138000 ← 10086","content":"正文…","time":"2026-10-14 12:30:00（北京时间）","source":"sms","sender":"1069012345678","device":"我的手机"}
```

2. 对端需要特定格式时配 `GENERIC_WEBHOOK_TEMPLATE`，用占位符 `{{title}}` / `{{content}}` / `{{time}}` / `{{source}}` / `{{sender}}` / `{{device}}` 自定义请求体；模板能被解析为 JSON 就按 JSON 发送，否则按纯文本发送。示例：

```
{"phone":"13800138000","msg":"{{content}}","at":"{{time}}"}
```

3. 对端需要鉴权请求头（密钥不放 URL）时配 `GENERIC_WEBHOOK_HEADERS`，值为 JSON 对象字符串，如：

```json
{"Authorization":"Bearer sk-xxx","X-Api-Key":"yyy"}
```

该值不是合法 JSON 时会被忽略，不影响默认转发。短信网关、Home Assistant、n8n、自建脚本等任何第三方 API 都可用该模板接入。各渠道的变量名与配置位置见上文「变量与密钥」表；Cloudflare 在 Worker 的「变量和机密」页配置，其余平台在各平台教程对应的环境变量处配置。

### 3. 数据库

**v1.0.3 不涉及任何建表/改列**：通知配置与业务参数写入既有的 `settings(key TEXT PRIMARY KEY, value TEXT NOT NULL)` 表，旧库直接可用，无需手工执行 SQL。

D1 的 `messages` 表需要包含 `source`（区分短信/通知）与 `deleted_at`（软删除/撤销）列。全新部署直接执行 [schema.sql](../schema.sql)；旧库升级执行：

```sql
ALTER TABLE messages ADD COLUMN source TEXT NOT NULL DEFAULT 'sms';
ALTER TABLE messages ADD COLUMN deleted_at TEXT;
ALTER TABLE messages ADD COLUMN starred INTEGER NOT NULL DEFAULT 0;
ALTER TABLE messages ADD COLUMN read_at TEXT;
```

## 二、推送接口规格

两个公开接口共用 `RECEIVE_TOKEN` 鉴权（token 放 query 或 body 均可）：

### 1. 短信接收 `POST /api/receive`（安卓 App 专用）

```
POST https://<你的域名>/api/receive?token=<RECEIVE_TOKEN>
Content-Type: application/json

{
  "name": "我的手机",
  "sim": "13800138000",
  "from": "1069012345678",
  "content": "您的验证码是 734752，5 分钟内有效",
  "time": "2026-10-14 12:29:59"
}
```

### 2. 通用推送 `POST /api/push`（各平台通知）

```
POST https://<你的域名>/api/push
Content-Type: application/json

{
  "token": "<RECEIVE_TOKEN>",
  "source": "notify",
  "sender": "备份脚本",
  "name": "通知网关",
  "content": "数据库备份完成，耗时 3 分 12 秒",
  "time": "2026-10-14 03:00:00"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `token` | 是 | 鉴权令牌 |
| `content` | 是 | 消息正文（`text`/`message`/`msg` 也可） |
| `source` | 否 | 来源标识，默认 `notify`；网页「来源筛选」用，可自定义（如 `cron`、`alert`） |
| `sender` | 否 | 来源标题（主机名/App 名/脚本名） |
| `name` | 否 | 设备标签名（自定义命名），默认「通知网关」，与短信标签并列展示 |
| `time` | 否 | 事件时间，缺省取服务器当前时间；支持时间戳或 `YYYY-MM-DD HH:MM:SS` 文本 |

响应：`{"success":true,"device_id":17,"duplicated":false}`（`duplicated=true` 表示重复消息已忽略，不会重复转发到通知渠道）

## 三、各平台接入方法

### 安卓（短信 + 应用通知）—— SmsForwarder

1. 安装开源 App「短信转发器」([pppscn/SmsForwarder](https://github.com/pppscn/SmsForwarder))
2. 通用设置里**开启「转发短信广播」总开关**
3. 新建「Webhook 通道」：URL 填 `/api/receive?token=<RECEIVE_TOKEN>`，消息模板：

```json
{"name":"我的手机","sim":"13800138000","from":"{{FROM}}","content":"{{SMS}}","time":"{{DATE}}"}
```

> 要点：`name` 填自定义设备名（网页标签显示它，改名会生成新标签）；`sim` 直接填手机号（卡片右下角显示，双击复制）；`content` 必须用 `{{SMS}}` 变量。
> 应用通知转发：再加一条「App 通知」转发规则，模板里 `sender` 用 `{{APP_NAME}}`、`content` 用 `{{MSG}}`，改推 `/api/push`。

**装好后能收发，不代表长期可靠。** 安卓会省电杀进程、断网、限制后台，锁屏/重启后最容易“静默失联”。完整的逐项检查清单与各厂商设置路径见独立文档：**[安卓 SmsForwarder 转发保活指南](安卓SF保活指南.md)**。最低限度请确认：

1. SmsForwarder 已授予短信、通知读取、后台运行权限；
2. 系统电池优化设为「不限制 / 允许后台活动」，并允许自启动；
3. 锁屏后发一条测试短信，网页能看到；重启手机后再发一条，仍能看到；
4. 双卡手机为两张 SIM 都建规则，或确认目标卡已覆盖；
5. 换网络（Wi‑Fi ↔ 移动数据）后 5 分钟内再测一条。

### iOS —— 快捷指令（Shortcuts）

1. 快捷指令 → 自动化 → 新建「个人自动化」→ 选「收到短信/信息」
2. 添加操作 →「获取 URL 内容」：

   - 方法：POST，请求体 JSON：

### Linux —— curl / 脚本 / systemd

最简单的一行：

```bash
curl -s -X POST https://<你的域名>/api/push \
  -H "Content-Type: application/json" \
  -d '{"token":"<RECEIVE_TOKEN>","sender":"web-01","content":"Nginx 已重启"}'
```

定时/事件通知示例（`/usr/local/bin/notify.sh`）：

#!/bin/bash

## 四、安卓 SmsForwarder 转发保活指南

安卓端“配置成功”只完成了一半，真正决定能不能长期收到的是**后台存活**。这里给一份可执行清单；分机型菜单路径、权限逐项解释、锁屏/断网/重启后的自检与恢复步骤，见 **[安卓 SmsForwarder 转发保活指南](安卓SF保活指南.md)**。

必做五件事：

| 项目 | 目标状态 | 说明 |
|---|---|---|
| 电池优化 | SmsForwarder 为「不限制 / 允许后台活动」 | 各厂商入口名称不同，通常在「设置 → 电池 → 应用耗电管理」；未设置会被休眠 |
| 自启动 / 后台启动 | 允许 | 重启后能否自动恢复转发的关键，通常在「权限管理 → 自启动」 |
| 后台弹出/锁屏运行 | 允许（如有该项） | 部分厂商锁屏后立即冻结后台应用 |
| 通知权限 | 允许通知、允许常驻通知 | 应用通知转发依赖通知读取权限；关闭会导致“应用通知收不到” |
| 省电模式/超级省电 | 测试时关闭，长期加入白名单 | 省电模式会强制断网/冻结后台 |

自检节奏（建议部署当天做一次，之后每月一次）：

1. 屏幕常亮 → 发测试短信 → 网页出现；
2. 锁屏 1 分钟 → 发测试短信 → 网页出现；
3. 切移动数据（关闭 Wi‑Fi）→ 发测试短信 → 网页出现；
4. 重启手机 → 不打开 App → 发测试短信 → 网页出现；
5. 放置 8 小时后 → 再发一条 → 网页出现。

任一步失败：先看 SmsForwarder 内「发送记录」是否有失败原因；再去系统电池/自启动/后台限制里放行；仍失败时重新打开 App 触发一次，观察是否恢复。**本指南不涉及 root、不修改系统分区、不保证在所有定制 ROM 上 100% 存活**，机型差异必须以真机实测为准。

想拿到**针对自己机型**的逐项设置路径，可把手机品牌与完整型号、Android 版本、系统版本（如 HyperOS / ColorOS / MagicOS / One UI）、SmsForwarder 版本、当前故障现象提供给 AI，让 AI 按该机型给出清单；模板、要求与实际局限见保活指南第十节「按你的机型生成专属保活方案」。

|---|---|
| 接口鉴权 | 无 token 请求应返回 403 unauthorized |
| 通用推送 | 用上面任一示例发一条，网页「通知」来源下可见，已配置的通知渠道同步收到 |
| 短信链路 | 手机发一条真实短信 → 网页「短信」来源可见 + 验证码识别 + 通知渠道转发 |
| 来源筛选 | 管理页工具栏「来源筛选」下拉切换：全部 / 短信 / 通知及自定义来源 |
| 九语言切换 | 管理页与登录页内置九语言（简体中文 / 繁體中文 / English / 日本語 / 한국어 / Español / Français / Deutsch / Português (BR)），右上「🌐」菜单选择后整页切换，选择记在浏览器本地；也可直接访问 `https://你的域名/?lang=ja` 等直连。旧链接 `?lang=zh` / `?lang=en` 仍然兼容（自动归一化为 zh-CN / en） |
| 导出与筛选 | 点「导出 CSV / JSON」下载当前筛选结果；切换「近 7 天」「每页 50」后列表与导出随之变化 |

## 六、常见问题

- **推了消息网页没刷新？** 管理页走长轮询自动刷新（默认最长 25 秒挂起，可用 `WAIT_MAX_SECONDS` 调整）；切回页面时会立即补拉一次；也可手动切一下来源筛选触发加载。
- **手机浏览器上界面挤 / 登录框被放大？** 已按移动端适配（安全区、16px 输入框防 iOS 自动放大、加大触控目标）；若仍异常，清一下该站点缓存后重试。
- **Netlify 上长轮询总是报错？** 把 `WAIT_MAX_SECONDS` 设为 `8`（低于 Functions 的 10s 上限）。
- **通知渠道没收到？** 先在管理页「设置 → 通知设置」确认该渠道已启用、必填字段显示“已配置”，然后点该渠道的「发送测试通知」：成功说明凭据没问题，再检查总开关与转发类型是否包含当前消息类型（`duplicated:true` 的消息不会转发）。仍然失败时看部署平台日志有无 `notify forward failed:`（日志中的 URL 已脱敏）。
- **想换标签名？** 点设备标签后的「✎」重命名（设为别名），或点「⇄」把该标签的消息合并到另一台设备；无消息的标签可直接「×」删除。
- **消息能保留多久？** 管理页「业务设置」里的保留天数控制（旧变量 `RETENTION_DAYS` 兼容），默认 30 天，每天 UTC 17:00（北京时间凌晨 1 点）自动清理。
- **升级后旧的通知变量还要留着吗？** 不需要的话可以在设置页点「从环境变量导入」把值搬进数据库，再删掉平台里的旧变量；不导入也能继续用，数据库没有键时自动回退。
- **两个管理员同时改设置，谁生效？** 后保存的一方会提示「设置已被其他会话修改」并整批不写入，重新打开页面再保存即可，不会出现半套配置。
