## 三、验收中发现的缺陷（已修）

**UX-21：长按抬手后，刚选中的卡片被反选回去（表现为「多选打开了但 0 选中」）**

- **复现**（ego lite 真实触摸）：390px 下 `touchstart` 保持 750–900ms，计时器 500ms 触发并正确选中 1 条（t=600ms 时 `1 selected`），**抬手后回到 `0 selected`**，多选态仍在。
- **病因**：`touchstart` 里的 500ms 长按计时器把 `suppressClick = true`，并用 `setTimeout(400)` 复位。触摸→点击在移动端还有最多约 300ms 的补发延迟，慢抬手（>900ms）时窗口已过，补发的 `click` 落到同一张卡片上，`toggleSelCard` 把刚选中的那条又切掉。这是纯时间窗方案的固有缺陷，与设备、抬手快慢强相关。
- **修复**：改成按「哪张卡」屏蔽——记录 `suppressClickId = card.dataset.id`，`click` 只在命中的同一张卡上吞一次；新手势 `touchstart` 时清标记，避免误吞用户下一次真实点击。
- **复验**：同一脚本 t=600 / t=900 / 抬手 +500ms 三处采样均为 `1 selected`，补选 2 条后 `3 selected`，`Esc` 后归零。
- **回归**：新增结构断言 `UX-21`（`tests/run.mjs`，874 项），六平台重新同步，`gen_app.py --check` 通过。

> Service Worker 用的是 **network-first**（`smstoweb-shell-v2`，仅断网时回落到缓存），加上主页面 `no-cache + ETag`，正常网络下不会拿到旧 HTML；GPT 提的「旧 SW 混入旧页面」在本项目结构下风险低，但仍建议部署后开一次无痕窗口对照。

**仍需登录态人工确认（无法在离线验收里代替）**：

1. 两个域名分别登录，确认鉴权与跳转正常；
2. 核心链路：查看、复制验证码、筛选、翻页、详情；
3. 多选闭环（数据面）：选 3 条 → 只影响这 3 条 → 删除 → 撤销恢复 → 未选中的不动 → 刷新不留残留选择态；
4. 真机手势：iOS Safari 长按不弹系统文本选择/上下文菜单，滚动不误触发多选。
