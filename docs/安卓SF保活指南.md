# 安卓 SmsForwarder 转发保活指南

> 适配版本：**v1.0.3**　适用对象：用安卓手机 + SmsForwarder（短信转发器）把短信/应用通知转发到本项目的用户。
>
> 本文只讲**系统侧与 App 侧如何让转发长期可靠**；网关地址、token、消息模板见 [多平台接入部署指南](多平台接入部署指南.md) 第三节。
> **重要**：安卓厂商的菜单名称、层级和默认策略一直在变。文中路径是“常见位置”，**以你真机上的实际菜单为准**；标有「需核实」的条目请在现场逐项确认，不要照抄。
> 本文不涉及 root、不修改系统分区、不绕过厂商安全机制，也不承诺在所有定制系统上 100% 存活。

---

## 一、先分清两类“收不到”

排障前先定位，避免在错误的方向上折腾：

| 现象 | 更可能的原因 | 先看哪里 |
|---|---|---|
| 网页一条都没有，App 内“发送记录”也没有 | 短信没触发转发规则 / 短信权限缺失 / 规则未命中 | SmsForwarder 规则与发送记录 |
| App 内发送记录有失败（超时、403、429） | 网络、token、域名、限速 | 失败原因文本 + 网关日志 |
| App 内发送记录成功，但通知渠道没收到 | 网关侧通知配置/渠道未启用 | 管理页「设置 → 通知设置」→ 发送测试通知 |
| 白天正常，锁屏/夜里/重启后断 | 后台被系统冻结或杀死 | 本文第三、四节 |

先做一次**最小链路验证**：手机浏览器打开 `https://<你的域名>/`，能打开说明网络与域名正常；再用 SmsForwarder 的“发送测试/发送记录”发一条，网页能看到即链路打通。链路没通之前，不要先去改电池设置。

## 二、权限清单（缺一不可）

在系统「设置 → 应用 → SmsForwarder → 权限」中逐项确认：

| 权限 | 作用 | 不开的后果 |
|---|---|---|
| 短信（读取/接收） | 读取新短信内容 | 短信转发完全不工作 |
| 通知使用权（通知读取） | 读取其他 App 的通知 | “应用通知转发”收不到 |
| 通知（发送通知） | 显示常驻/状态通知 | 前台服务不可见，容易被系统清理（部分系统必需） |
| 后台运行 / 后台活动 | 允许 App 在后台存活 | 锁屏或切后台后停止 |
| 自启动 / 开机启动 | 重启后自动恢复 | 重启手机后必须手动打开 App 才恢复 |
| 忽略电池优化 | 不被省电策略休眠 | 数十分钟到数小时后静默失联 |
| 移动数据 / WLAN（后台联网） | 后台允许联网 | 息屏后无法发出请求 |
| 悬浮窗 / 后台弹出（部分厂商） | 部分系统用它判定“活跃应用” | 部分 ROM 上后台被立即冻结（**需核实**） |

> 小米/红米、OPPO/一加/realme、vivo/iQOO、荣耀、华为/鸿蒙等机型还有额外的“后台弹窗”“锁屏后运行”“应用速冻”“深度睡眠”等开关，名称不同，见第四节。

## 三、SmsForwarder 内需要确认的设置

以下名称以 App 内实际界面为准（不同版本可能叫法不同，**需核实**）：

1. **转发开关**：通用设置里的「转发短信广播」总开关必须打开；只开规则不开总开关是最常见的“配了但不发”。
2. **规则匹配**：确认规则匹配的是“接收短信”，而不是仅“发送短信”；双卡手机确认两张卡都在规则覆盖范围内（有的版本按 SIM 卡槽过滤）。
3. **通道配置**：Webhook 地址必须是 `https://<你的域名>/api/receive?token=<RECEIVE_TOKEN>`（或 POST + `Authorization` 头）；模板里 `content` 用 `{{SMS}}`，不要写死文本。
4. **失败重试**：若 App 提供重试/重发设置，建议开启（例如失败后重试 1~2 次）；没有该选项就依赖网关侧通知重试（与本项无关，仅影响网关向第三方渠道转发）。
5. **发送记录**：定期看“发送记录”，成功/失败都有时间与原因；这是判断“手机侧还是网关侧问题”的第一证据。
6. **电池/后台入口**：若 App 内提供“忽略电池优化”“自启动”引导按钮，优先从 App 内跳转设置，成功率比手动找菜单高。

## 四、系统侧逐项设置（重点是“别被系统休眠”）

按重要性排序，逐项做完再测试：

| 项目 | 目标状态 | 常见入口（以真机为准，**需核实**） |
|---|---|---|
| 电池优化 / 应用耗电管理 | 不限制、允许后台活动 | 设置 → 电池 → 应用耗电管理 → SmsForwarder → 不限制 |
| 省电模式 / 超级省电 | 测试时关闭；长期使用需把 App 加入允许名单 | 设置 → 电池 → 省电模式；部分机型有“超级省电”独立开关 |
| 自启动 / 开机自启 | 允许 | 设置 → 应用管理 → 权限管理 → 自启动（或“手机管家 → 自启动管理”） |
| 后台活动 / 后台弹出 | 允许 | 设置 → 应用管理 → SmsForwarder → 后台弹出界面/后台运行 |
| 锁屏清理 / 休眠清理 | 不清理该 App | 手机管家/安全中心 → 清理加速 → 白名单（名称因厂商而异，**需核实**） |
| 应用速冻 / 深度睡眠 | 加入白名单/不冻结 | 部分厂商“应用速冻”“休眠应用”列表，需手动移出 |
| 数据/流量限制 | 后台数据与 WLAN 均允许 | 设置 → 应用 → 流量使用 → 后台数据 / 无限流量 |
| 通知类别 | 允许通知，常驻通知可见 | 设置 → 应用 → 通知 → 允许；常驻/前台服务通知不要屏蔽 |

### 4.1 厂商差异（常见路径示例，务必按真机核对）

| 厂商 / 系统 | 电池与后台常见位置（**需核实**） | 额外注意 |
|---|---|---|
| 小米 / 红米（MIUI / HyperOS） | 设置 → 应用设置 → 应用管理 → SmsForwarder → 省电策略（无限制）+ 自启动；手机管家 → 应用管理 → 权限 → 自启动 | “省电策略”默认智能限制；还有“锁屏后清理内存”需设为不清理 |
| 华为 / 荣耀（EMUI / HarmonyOS / MagicOS） | 设置 → 电池 → 启动管理（手动管理：允许自启动/关联启动/后台活动）；手机管家 → 应用启动管理 | 关闭“自动管理”改为手动三项全开；部分版本有“休眠时保持网络连接” |
| OPPO / 一加 / realme（ColorOS） | 设置 → 电池 → 应用耗电管理 → 允许后台运行；设置 → 应用 → 自启动管理 | “智能省电”与“睡眠模式”需把 App 加白名单；部分机型有“冻结”列表 |
| vivo / iQOO（OriginOS / Funtouch） | 设置 → 电池 → 后台耗电管理 → 允许后台高耗电；i管家 → 自启动管理 | “后台高耗电”不开会在息屏后断网；还有“睡眠模式”白名单 |
| 三星（One UI） | 设置 → 电池 → 后台使用限制 → 从“休眠应用”中移除；设置 → 应用 → 特殊访问权限 → 电池优化 → 不优化 | “深度休眠应用”会自动加入，需手动移出 |
| 原生 Android / Pixel / 类原生 | 设置 → 应用 → 特殊应用权限 → 电池优化 → 不优化；设置 → 应用 → SmsForwarder → 电池 → 不受限制 | 相对宽松，但“自适应电池”仍可能限制后台 |
| 其他定制 ROM / 企业管控设备 | 以厂商文档为准 | 若被 MDM 策略限制，普通设置可能无效，需要管理员放行 |

### 4.2 Android 版本差异（通用说明，具体行为以真机为准）

- **Android 6~9**：主要受 Doze/应用待机影响，重点是“忽略电池优化”。
- **Android 10~11**：后台启动与位置/网络权限更严格，重点是“后台启动”“后台联网”开关。
- **Android 12~13**：通知权限改为运行时授权；精确闹钟、前台服务限制更严，重点是通知授权与省电策略。
- **Android 14~16**：前台服务类型与后台任务限制进一步收紧，部分系统会要求 App 声明前台服务类型才能长期驻留（**需核实**你的系统版本与 App 版本）。
- 系统大版本升级后，厂商常会重置省电白名单；**每次系统升级后请重新做第五节自检**。

## 五、部署后自检流程（建议当天一次，之后每月一次）

按顺序做，任一步失败先停下排查，不要跳到下一步：

1. **亮屏测试**：手机解锁、屏幕常亮 → 用另一部手机发一条短信 → 网页 1 分钟内出现；
2. **锁屏测试**：锁屏等待 1~2 分钟 → 再发一条 → 网页出现；
3. **断 Wi‑Fi 测试**：关闭 Wi‑Fi、仅用移动数据 → 再发一条 → 网页出现；
4. **重启测试**：重启手机，**不要手动打开 SmsForwarder** → 再发一条 → 网页出现（验证自启动）；
5. **静置测试**：静置 6~8 小时（最好跨过一次夜间）→ 再发一条 → 网页出现（验证不被冻结）；
6. **双卡测试**：给卡 1、卡 2 各发一条（或在规则里覆盖两张卡）→ 两条都出现；
7. **应用通知测试**（如启用）：让任意 App 弹一条通知 → 网页「通知」来源出现。

记录每次测试的时间与结果，出问题时能快速定位是“哪一类场景失效”。

## 六、失联后的恢复步骤

| 症状 | 处理顺序 |
|---|---|
| 重启后完全不再转发 | 打开一次 SmsForwarder，确认总开关仍在；检查“自启动/开机启动”是否被系统升级重置；必要时重新授予权限 |
| 锁屏一段时间后不再转发 | 检查电池优化是否被改回“智能限制”；把 App 从“休眠/速冻/深度睡眠”列表移出；关闭省电模式再测 |
| 切到移动数据后失败 | 检查后台数据权限与“省电模式限制后台流量”；确认 APN 正常（浏览器能上网） |
| App 发送记录显示 401/403 | token 不对、URL 拼错、或网关开启了登录但未带正确 token；对照网页端「接入令牌」 |
| App 发送记录显示 429 | 触发写入限速（默认每分钟 120 次），降低发送频率或等待自动恢复 |
| 发送记录显示超时/网络错误 | 域名解析、HTTPS 证书、平台冷启动延迟；先在手机浏览器打开站点确认可达 |
| 网页有记录但通知渠道没收到 | 转去管理页「设置 → 通知设置」用“发送测试通知”排查，与本保活无关 |
| 某次系统更新后突然失效 | 厂商重置了后台策略的概率最高；按第五节完整重测一遍 |

恢复后不要只测“亮屏一条”就结束，至少补做锁屏 + 重启两项。

## 七、长期维护建议

- **每月一次**按第五节做锁屏与重启两项抽测即可；系统升级、换机、换卡后必须完整重测。
- 手机同时装了“清理大师/安全卫士”类应用时，把 SmsForwarder 加入其白名单，否则会被第三方清理。
- 双卡用户给两张卡都建规则，或明确只转发其中一张；避免“换了主卡就收不到”。
- 不要把 SmsForwarder 放在“工作资料/分身空间”里，部分系统会限制其后台联网。
- 不需要 root；不建议用“强制停止后自动拉起”的第三方工具，容易与系统策略冲突。
- 如果长期稳定性要求很高，可考虑备用方案：另一台常驻设备（旧手机/树莓派）同时转发，或改用 iOS 快捷指令/服务端脚本作为补充链路。

## 八、常见误区

1. **“App 能打开就代表在运行”**：切后台后进程可能已被冻结，必须用锁屏/静置测试验证。
2. **只配规则不配总开关**：规则再多，总开关关着也不会转发。
3. **关闭通知权限**：应用通知转发依赖通知读取；同时常驻通知被屏蔽会降低存活率。
4. **测试时充电+亮屏，结论失真**：充电与亮屏会临时放宽后台限制，必须锁屏、拔线、静置后再测。
5. **把省电模式当常态**：省电/超级省电会强制限制后台网络，保活与省电本质冲突，需要做取舍。
6. **系统升级后不重测**：大版本升级重置白名单是常见现象。
7. **只看网页不查 App 发送记录**：无法区分手机侧失败还是网关侧失败，排查会绕远路。

---

## 九、边界与不保证事项

- 本文提供的是通用排查方法与常见路径，**不保证在所有厂商/系统版本/定制 ROM 上完全一致或 100% 存活**。
- 不同 SmsForwarder 版本的菜单名称、是否提供“开机启动/重试”等选项可能不同，以 App 内实际界面为准。
- 企业 MDM、儿童模式、隐私空间、系统级“冻结”策略可能使普通用户设置无效，需要设备管理员放行。
- 本项目只接收 HTTP 推送，无法感知手机端是否被杀死；若需要“失联告警”，可另配心跳脚本定期 `POST /api/push`，再用网关侧或第三方监控判断超时。

## 十、按你的机型生成专属保活方案

本文的厂商差异表只能覆盖常见路径。**具体到你的手机，最省事的做法是把机型和系统信息提供给 AI，让 AI 针对该机型给出逐项设置清单**（你也可以直接把下面模板发给任意你常用的 AI 助手）。

建议一次提供这些信息（缺项越多，给出的路径越泛化）：

| 需要提供 | 示例 | 用途 |
|---|---|---|
| 手机品牌 + 完整型号 | 小米 Redmi Note 12 Turbo / 华为 Mate 60 Pro | 定位厂商 ROM 与具体机型策略 |
| Android 版本 | Android 13 / 14 / 15 | 判断前台服务与后台限制规则 |
| 厂商系统名称及版本 | HyperOS 1.0 / ColorOS 14 / MagicOS 8 / One UI 6 | 决定菜单层级与开关名称 |
| SmsForwarder 版本 | 3.x（App「关于」里可查） | 判断是否提供开机启动/重试等选项 |
| 当前问题 | 锁屏 10 分钟后停止 / 重启后不自启 / 收不到短信 | 缩小排查范围 |

可直接复制这段模板：

```text
我的手机：<品牌> <完整型号>
Android 版本：<如 14>
系统版本：<如 HyperOS 1.0 / ColorOS 14 / MagicOS 8 / One UI 6>
SmsForwarder 版本：<如 3.x>
问题：<锁屏后停止 / 重启后不自启 / 收不到短信 / 其他>
请按我的系统版本，给出：1) 电池与后台设置的逐项路径；2) 自启动与后台活动权限；3) 通知权限与前台服务；4) 锁屏/重启/切网三项验证步骤。
```

对 AI 输出的要求（同样适用于你自己核对）：

- 路径应尽量对应你提供的大版本；**菜单名称不确定时，应明确标注「需核实」，不能编造**。
- 不同 ROM 的开关名称不同（如“应用速冻”“深度睡眠”“休眠时保持网络连接”），以真机实际界面为准。
- AI 给出的是操作建议，**不等于你的机型一定能长期存活**；仍要按第五节自检并记录结果。
- 不要采纳任何要求 root、刷机、破解系统或安装“强制保活”外挂的建议作为常规方案。
